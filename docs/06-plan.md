# 06. План работ

Оценка — ориентир для одного сильного full-stack разработчика. Вдвоём (бэк + фронт) — 8–10 недель.

## Принципы

1. **Рискованное — раньше**: сразу после фундамента — сквозной срез «товар → корзина → заказ → оплата в песочнице → вебхук».
2. **Внешние процессы — с первого дня**: эквайринг, хостинг в РБ + БелГИЭ → Торговый реестр, доступ к API YCLIENTS, OAuth-приложения, контент. Это и есть критический путь.
3. Каждый этап заканчивается демо на staging.

## Чек-лист внешних процессов (неделя 0)

- [ ] Выбран эквайер (bePaid / webpay), подана заявка, получены тестовые доступы
- [ ] Хостинг в РБ (желательно с аттестованной платформой), заявка на регистрацию в БелГИЭ
- [ ] Домен (.by — если нужен ЕРИП)
- [ ] Заявление в Торговый реестр (после БелГИЭ)
- [ ] Доступ к API YCLIENTS, company_id, ID формы виджета
- [ ] Google Cloud: OAuth consent screen, client id/secret; домены, ссылка на политику
- [ ] Яндекс OAuth-приложение (oauth.yandex.ru)
- [ ] SMTP (email уведомлений), при необходимости SMS-шлюз
- [ ] Яндекс.Метрика (+ GA4), Яндекс.Вебмастер, Google Search Console
- [ ] Юр. тексты: оферта, возврат, политика ПД, политика cookie, доставка и оплата
- [ ] Реквизиты для сайта: УНП, юр. адрес, номер Торгового реестра, режим работы
- [ ] Шаблон Excel для товаров и дедлайн по контенту/фото

## Тестирование (минимум)

- Unit/Feature (Pest): калькулятор цены и промокодов; матрица доставка×оплата; резерв при конкуренции; вебхуки (подпись, повтор, неверная сумма, оплата отменённого заказа); переходы статусов; политики доступа (IDOR); OAuth-ошибки; анонимизация.
- Browser (Pest 4 / Playwright): полный путь покупки на мобильном вьюпорте; вход/регистрация; fallback YCLIENTS.
- Lighthouse CI: главная и каталог ≥ 90 mobile.

- Короткая видеоинструкция для администратора.
