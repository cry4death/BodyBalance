# 05. Риски (по убыванию серьёзности)

## 1. Деньги и остатки — критично

| Угроза | Мера |
|---|---|
| Два покупателя берут последнюю единицу одновременно | Резерв в транзакции с `lockForUpdate()` на строке товара; повторная проверка при подтверждении; понятное сообщение + обновление корзины |
| Клиент оплачивает заказ, который уже отменён по истечении резерва | TTL резерва (напр. 30 мин) для онлайн-оплаты; **срок жизни платёжной сессии строго меньше TTL резерва**; джоба освобождения резерва |
| Поддельный вебхук / подмена суммы | «Оплачен» — только по вебхуку с проверкой подписи: bePaid — RSA-подпись в заголовке `Content-Signature` (SHA256, публичный ключ из бэкофиса); webpay — `wsb_signature`. Сверять сумму, валюту, номер заказа. Return URL ничего не доказывает |
| Дубли вебхуков | Уникальный `provider_transaction_id`; повторная обработка — no-op |
| Двойная оплата одного заказа | Не создавать платёжную сессию для оплаченного заказа; вторая успешная оплата → флаг «к возврату» + алерт |
| Потерянные вебхуки | Ночная сверка с API эквайера; на странице возврата — опрос статуса |
| Ошибки округления | Деньги в копейках (int). У webpay — нюанс формата суммы в подписи (`1` vs `1.00`) |
| ЕРИП: оплата приходит через часы | Отдельный статус ожидания и более длинный резерв |
| Подбор промокодов | Rate limit на применение промокода |

## 2. Юридические блокеры РБ

Не зона ответственности разработчика, но без этого запуск невозможен. Данные — по профильным статьям 2026 г.; **подтвердить у юриста заказчика**.

- **Хостинг на территории РБ** у белорусского провайдера + **регистрация ресурса в БелГИЭ** (подаёт хостер, ~15 дней) — Указ №60 от 01.02.2010. Зарубежный VPS не подходит. Штраф для ИП/юрлиц — от 10 до 25 базовых величин.
- **Торговый реестр**: включение интернет-магазина — после регистрации в БелГИЭ.
- **Домен**: для ЕРИП — `.by` / `.бел` без редиректов на другой домен, зарегистрирован на то же лицо.
- **Обязательная информация на сайте**: наименование продавца, УНП, юр. адрес, номер и дата в Торговом реестре, контакты, режим работы, цены только в BYN, условия оплаты/доставки/возврата, оферта, политика ПД, политика cookie.
- **Эквайер проверяет готовый сайт** (оферта, возврат, реквизиты, контакты, логотипы платёжных систем) — подключение занимает недели → подать заявку в неделю 0.
- **Персональные данные** (Закон №99-З): отдельное согласие (не предзаполненный чекбокс), журнал согласий с версией политики; политика обработки ПД и cookie; cookie-баннер, где отказ так же прост, как согласие (позиция НЦЗПД); трансграничная передача (GA → США, Sentry, зарубежный SMTP) — решение юриста.
- **ОАЦ** (приказ №66 в ред. приказа №259 от 10.12.2024, с 01.03.2025): требования к технической защите ИС с ПД — уточнить у юриста; практично — хостинг с аттестованной платформой.

## 3. YCLIENTS

- **Виджет — чёрный ящик в iframe**: стилизуется только настройками YCLIENTS; ошибки внутри сайт не видит. Ловим только «скрипт не загрузился/не ответил за N секунд» → fallback. Плюс ручной рубильник в админке.
- **Доступ к API**: партнёрский токен — после регистрации разработчиком в маркетплейсе YCLIENTS; user-токен — `POST /auth`; заголовок `Authorization: Bearer <partner>, User <user>`. Условия для собственной интеграции студии — выяснить в неделю 0. Без API — ручная сверка (ТЗ допускает).
- **Маппинг категорий**: категории YCLIENTS почти никогда не совпадают 1:1 с пятью категориями сайта → таблица соответствия; цены «от»/диапазоны.
- **Аналитика записи**: iframe на чужом домене — конверсию напрямую не видно. Проверить, какие счётчики позволяет подключить сам YCLIENTS; иначе — микроконверсия «клик Записаться».

## 4. Макет

- **Шрифты без кириллицы**, **контраст** — см. [07-design-findings.md](07-design-findings.md).
- В макете, вероятно, нет состояний (ошибки, пусто, загрузка, нет в наличии, 320px) — придётся проектировать.
- Судя по классам `.btn-primary`, `.chip` — макет в HTML/CSS: запросить исходник, часть кода переносится в Blade-компоненты.

## 5. PageSpeed ≥ 90 (мобайл)

Измеримый критерий приёмки при большом количестве тяжёлых сторонних скриптов (Метрика, GA, YCLIENTS, карта, мессенджеры) и фото на главной.

- Шрифты: self-hosted woff2, subset (кириллица+латиница), только нужные начертания, preload 1–2 файлов, `font-display: swap`.
- Изображения: srcset, WebP/AVIF, явные `width/height` (CLS), `loading="lazy"` ниже первого экрана, `fetchpriority="high"` для hero.
- YCLIENTS — по клику/видимости; карта — статичное изображение; мессенджеры — ссылки; счётчики — после согласия и отложенно; Вебвизор — осознанно.
- Минимум JS на главной; Tailwind → маленький CSS; OPcache, Redis, кэш страниц.
- **Зафиксировать методику в договоре**: URL, Lighthouse mobile, медиана 5 прогонов, финальный контент.
- Lighthouse CI в пайплайне — бюджет производительности.

## 6. Авторизация

- Телефон как логин → для сброса/подтверждения нужен SMS (см. Q5).
- **Связывание аккаунтов**: привязывать OAuth к существующему аккаунту по email только если провайдер подтвердил email (`email_verified` у Google); иначе — вход паролем и привязка из профиля. Иначе возможен захват аккаунта.
- Rate limit: вход, регистрация, сброс пароля, промокод.
- Ошибки OAuth → понятное сообщение + вход по паролю.
- MFA для админки (встроено в Filament).
- Удаление аккаунта → анонимизация, заказы сохраняются.

## 7. Контент и сроки

- Сотни товаров с составом, применением, фото — главная причина срывов запуска. Импорт из Excel (шаблон заранее) и дедлайн на контент.

## 8. SEO-ожидания

- FAQ-сниппеты Google с августа 2023 показывает почти только авторитетным гос/мед сайтам.
- Звёзды за отзывы о самой студии (LocalBusiness, self-serving reviews) Google не выводит. Звёзды реальны только у товаров (Product + AggregateRating).
- Staging должен быть закрыт от индексации (иначе дубли).
